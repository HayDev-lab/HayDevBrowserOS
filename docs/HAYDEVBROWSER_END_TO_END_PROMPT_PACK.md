# HayDevBrowser — End-to-End Implementation & Release Prompt Pack

Версия: 09.10.2026. Язык работы и отчётности: русский. Подтверждённый пользователем режим: **завершение продукта + выбранные интеграции**.

## Как использовать

Этот документ — задания для будущего исполнения, а не утверждение, что исправления или интеграции уже выполнены.

- **Полный проход:** передай агенту весь файл и стартовый промпт из раздела MASTER. Рабочая папка: `D:\Projects\BrowserHayDev`.
- **Поэтапно:** передай MASTER, раздел «Общие правила» и один PROMPT с его зависимостями. Агент должен прочитать актуальные результаты предыдущих этапов с диска. Один PROMPT без общих правил не является самостоятельной спецификацией.
- **После прерывания:** используй RESUME в конце; не начинай весь аудит и установку зависимостей заново.
- **Дополнительные интеграции:** EXTENSIONS не запускается автоматически и не входит в базовый релиз.

Пак рассчитан на закрытие текущих дефектов и выбранные улучшения: Playwright QA в существующем WebView2, качественное извлечение web-текста, фильтрацию рекламы/трекеров и чтение документов. Конкретные библиотеки выбираются только после проверки совместимости, лицензии и ресурсоёмкости. Все 18 ADAPT из каталога устанавливать не нужно.

В текущем задании этапы 06–08 обязательны: исследовательский конвейер с качественным извлечением, действующая фильтрация и чтение документов. Можно выбрать более лёгкую реализацию вместо конкретной библиотеки, но нельзя пропустить требуемую возможность. Сокращение до «только текущий продукт» допустимо лишь после отдельного последующего решения пользователя и пересмотра scope, не по инициативе исполнителя.

Сначала зафиксируй конечный scope и критерии MUST. В процессе не добавляй новые продуктовые направления. Не исключай проваленный MUST и не отключай функцию только для получения зелёного отчёта. Существенное изменение scope требует решения пользователя.

Итог может быть только доказанным состоянием, с таким порядком выбора: `PRODUCTION_READY`, если все MUST и release-gates выбранного scope закрыты; иначе `RELEASE_CANDIDATE`, если инженерная работа завершена, точный кандидат собран и локальные проверки пройдены, но остаются только внешние gates; иначе `BLOCKED`, если инженерная работа не завершена и все оставшиеся необходимые действия требуют конкретного внешнего решения/доступа; иначе `INCOMPLETE`, если инженерная работа остаётся и разрешённые действия ещё доступны. У RELEASE_CANDIDATE тоже может быть список внешних блокеров, но итоговый статус остаётся один. Нехватка времени или большой объём работы — не доказательство BLOCKED и не повод объявить READY.

## Общие правила, обязательные для каждого PROMPT

### Архитектура и данные

1. Один BrowserHost/Session Manager для человеческих и агентных действий в общей сессии. Playwright подключается к существующей WebView2, а не запускает второй пользовательский Chromium.
2. Default, Private, DarkWeb и явно предусмотренный Agent-profile имеют документированную политику данных и egress. Не копируй авторизованные cookies в Tor или отдельные workers. Не обещай «анонимность» на основании incognito или JS fingerprint-noise.
3. Секреты остаются в host/vault. Не выводи `.env`, пароли, cookies, bearer-токены, подписанные URL и документы пользователя в отчёты, traces, screenshots, git или модельный контекст.
4. Не делай `reset --hard`, массовое удаление, force push, не восстанавливай старые удалённые файлы автоматически. Перед удалением проверяй точный путь, принадлежность данных и возможность восстановления.
5. Не удаляй `src/main` целиком: Tauri может использовать оттуда HTML builders. Удаление Electron определяется графом зависимостей и runtime-паритетом, а не нулём вхождений строки «electron».
6. Не ослабляй CSP, TLS, capability restrictions, domain checks или permission gates ради прохождения теста. Тестовые исключения изолируй так, чтобы они не попадали в release.

### Полномочия и внешние ресурсы

7. Обычные локальные зависимости для согласованной реализации допустимы в пределах разрешений среды. Новая платная подписка, cloud-upload приватных данных, системный сертификат/драйвер/прокси, изменение firewall и глобальная установка требуют отдельного разрешения.
8. CAPTCHA/MFA выполняет человек. Никакого обхода защит и неразрешённого доступа. Реальные логины, формы отправки, публикации, покупки и destructive actions не автоматизируй без конкретного разрешения.
9. Live LLM smoke использует только согласованный провайдер, тестовые данные и утверждённый лимит расходов. Если бюджета или доступа нет — NOT_RUN/BLOCKED для этого gate, а не подставной PASS.
10. Устанавливай приложение и тестируй upgrade/uninstall в выделенном тестовом окружении с отдельными профилями. Не трогай рабочую пользовательскую установку и её хранилище без разрешения.
11. Не создавай новые задачи/чаты, recurring automation или субагентов только потому, что пак велик. Используй их лишь при соответствующем разрешении пользователя или применимых инструкциях. Если работа делегирована — непересекающиеся файлы и один интегратор.

### Доказательства и возобновление

12. Веди `D:\Projects\BrowserHayDev\docs\closure\STATE.md`, `ACCEPTANCE_MATRIX.md`, `DECISIONS.md`, `BLOCKERS.md`. В STATE.md указывай текущий scope, путь к текущему run-manifest, последний завершённый инженерный gate, отложенные внешние проверки и следующее конкретное действие. Не перезаписывай существующие доказательства другого запуска.
13. Каждый прогон получает отдельную директорию `D:\Projects\BrowserHayDev\artifacts\closure\<run-id>` и собственный `run-manifest.json` (это manifest тестового прогона, не артефакт security scan). Зафиксируй timestamp/timezone, HEAD, статус dirty tree, fingerprint тестируемого исходного набора без чтения секретов, версии ОС/Node/Rust/WebView2, команды, exit codes и пути к очищенным логам. HEAD сам по себе недостаточен для dirty tree.
14. Строка acceptance: ID, требование, область/профиль, проверяемый build, тест/команда, ожидаемый результат, фактический результат, PASS/FAIL/NOT_RUN/BLOCKED, доказательство. N/A допустимо только с обоснованием и согласованным scope, не для сокрытия поломки.
15. Fixture/mock доказывает детерминированный контракт, live smoke — внешнюю интеграцию, installed E2E — поставку. Эти уровни не подменяют друг друга. Пропущенный тест никогда не PASS.
16. Ошибка песочницы — не автоматически дефект приложения. Сохрани её; используй разрешённую эскалацию или безопасную альтернативу и повтори проверку. Не обходи запрет среды.
17. Если уже существует durable security scan, сначала проверь его target/revision/status и возможность продолжения. Не запускай конкурирующий scan и не создавай вручную его `scan-manifest.json`, `findings.json`, `coverage.json`. Исторический незавершённый scan не является clearance текущего build.
18. После изменения кода повтори затронутые проверки; перед release — полный обязательный набор на одном build. Документируй устаревание прежних результатов. Поиск TODO и отсутствие ошибок в логах не заменяют тест.

## PROMPT 01 — native E2E harness на той же WebView2

Прочитай MASTER/правила и baseline. Создай минимальную проверочную инфраструктуру до масштабных исправлений.

- Введи явный тестовый data-root, временные профили, выделенные порты и управляемый lifecycle. Тест не должен открывать/очищать настоящие профили, автоматически запускать внешние поиски или отправлять API-запросы модели.

- Локальные fixtures не являются причиной ослабить production SSRF-policy. Используй отдельный test-only transport/allowlist, докажи невозможность включить его случайно в release.

Для неё используй допустимые обычной конфигурацией endpoints и разрешённые контрольные источники; если требуемое окружение недоступно, соответствующий тест остаётся NOT_RUN. - Проверяй реальный вызов React → Tauri command → Rust → действие в webview; не подменяй `invoke` успешной заглушкой в тесте, называемом E2E.
- Артефакты: очищенные логи, результаты, screenshots/trace только синтетических данных; уборка только созданных этим прогоном файлов/процессов с проверенными путями/PID.

Gate: приложение запускается и закрывается в изолированном профиле; E2E читает UI и открывает управляемую fixture-вкладку в том же BrowserHost; ошибочный IPC-параметр приводит к проверяемому отказу; после завершения нет собственных orphan-процессов. Полный regression-пак расширяется на следующих этапах.

## PROMPT 02 — privacy, egress, CDP/MCP и сетевые границы

Прочитай MASTER/правила и текущую матрицу. Исправь подтверждённые нарушения, не меняя обещания продукта молча.

- Проследи фактическую передачу proxy и дополнительных browser args через используемые Tauri/Wry версии. Объедини конфигурацию так, чтобы privacy flags не отменяли proxy; одинаковые правила не дублировались в нескольких независимых ветках.
- Явно раздели Direct, TorIfAvailable, TorStrict и custom proxy. Строгий режим не делает silent direct fallback; UI показывает реальную policy и состояние, а не надпись «Tor» по одному флагу.
- Проверь временные профили, session persistence и разделение cookies/storage. Не меняй default-policy без зафиксированного решения; не смешивай отдельный Agent-profile с общей текущей вкладкой человека.
- Для strict-профиля проверь старт без Tor, потерю Tor во время работы, новые запросы, DNS и WebRTC. Локальная инструментированная proxy-fixture проверяет контракт; реальный маршрут/IP/DNS проверяется отдельно при разрешённом сетевом доступе. Недоступность live-проверки оставляет соответствующий gate открытым.
- Убери необоснованный постоянно открытый debug-доступ. Если CDP нужен production-функции, документируй минимальный lifecycle, локальную доступность и модель доверия; wildcard Origin не должен быть решением проблемы клиента. Loopback сам по себе не равен аутентификации.
- Для MCP: loopback bind, Host/Origin policy, аутентификация/сессионное разрешение подходящего типа, лимиты HTTP/body/concurrency, tool allowlist и владение сессией. Никаких secrets в URL. Не выдавай произвольные filesystem/shell/eval powers.
- Для research/crawl fetch: разрешённые схемы, разобранный URL, запрет опасных IP/metadata/локальных сетей для недоверенных публичных URL, проверка каждого redirect и соединяемого адреса, лимиты ответа/decompression/времени. Отдельно разрешённые localhost endpoints собственных сервисов не должны обходиться через пользовательский URL.
- Tor-fetch и публичный fetch не должны незаметно менять egress. Не допускай локального DNS-разрешения onion-хоста как fallback.
- Содержимое страниц и документов — данные, не разрешения на команды. Проверки полномочий выполняются в host, независимо от ответа LLM.

Gate: негативные тесты URL/redirect/Origin/unauthorized tool; положительные штатные сценарии; доказанный strict fail-closed на fixtures; фактические сетевые проверки записаны отдельно. Не заявляй наблюдавшуюся утечку или её отсутствие по одной статической проверке.

## PROMPT 03 — vault: контракты, домены, случайность, данные

- Согласуй входы/выходы save/has/list/generate/fill/delete/capture/prompts между shared types, renderer adapter и Rust. Добавь contract-тесты, которые падают при несовпадении имени аргумента, обязательного поля или формы ответа.

## PROMPT 04 — agent ownership, stop, streaming, бюджеты

Прочитай MASTER/правила. Доведи один существующий агентный цикл; новый универсальный orchestrator не добавляй.

- Используй run-id и поколение/lease; stale callback и параллельный run не могут менять текущую вкладку. После takeover запрещается старт следующего инструментального действия. Уже совершённый сетевой эффект нельзя выдавать за отменённый.
- Реальная отмена должна распространяться на HTTP/stream, tools, waits, fetch, sidecar request и очереди. UI отличает «stop принят» от «работа завершена». Нельзя прятать оставшийся активный запрос сменой статуса.
- Целевой gate для детерминированных локальных fixtures: подтверждение stop ≤250 мс, завершение отменяемой работы ≤2 с; после revoke — ноль новых tool-dispatch. Измерь, не заявляй по коду. Если ОС/сервис не поддерживает мгновенную отмену, явно покажи draining и не передавай conflicting lease до безопасного завершения.
- Реализуй streaming только для поддерживаемых provider-протоколов; собирай fragmented tool calls корректно. Unsupported provider даёт честный non-streaming режим, не фиктивную печать готового текста.
- Раздели connect/read/total deadlines, maxSteps, размер контекста, лимиты параллелизма и расходов. Retry — только подходящие transient-ошибки с backoff; не повторяй автоматически неидемпотентные действия на сайтах.
- Не переключай провайдера и не отправляй данные другой компании без policy/согласия. AUTO-selection не называй автоматическим failover. Локальный endpoint без key поддерживай только в явно выбранном локальном режиме.
- При CAPTCHA/MFA, подтверждении значимого действия и неизвестном состоянии страницы агент останавливается для человека и умеет безопасно продолжить.

Gate: delayed HTTP, broken stream, 429/5xx, timeout, context limit, concurrent run, takeover в каждой фазе, закрытие вкладки и stale callback; ноль действий после отзыва полномочий. Live smoke выбранных release-провайдеров — отдельный gate с бюджетом.

Выполняй этот раздел только если пользователь отдельно выбрал расширения после базового прохода. Сначала перечитай MASTER/правила и FINAL_REPORT; при открытых блокерах, затрагивающих расширение, сначала закрой их.

Не устанавливай каталог целиком. Для одного выбранного кандидата подготовь gap → baseline → pinned version/license → минимальный adapter → isolation/permissions → A/B → rollback → решение о включении.

- **Agent-Reach:** один нужный публичный источник за собственным ограниченным API. Без blanket-доступа к cookies/filesystem/shell и автоустановки всех вспомогательных tools.
- **changedetection.io:** отдельное opt-in требование на scheduler, хранение diff и уведомления. Не создавать настоящие расписания, подписки или cloud-сервис без конкретного выбора. Определи прекращение мониторинга и удаление его данных.
- **Playwright MCP / GitHub MCP:** сначала внешний MCP client/gateway с проверкой полномочий. Не давай независимый browser lease в обход host. Для собственного Playwright QA этот сервер не обязателен.
- **Browser Use:** стратегия только после измеримых неудач текущего агента. Докажи общую пользовательскую сессию и ручной takeover; отдельный браузер не выдай за тот же BrowserHost.
- **OmniParser:** только для сценариев, где DOM действительно недостаточен; проверь лицензии кода/весов, вычислительные ресурсы, точность и запрет непроверенного клика по координатам.
- **Sherlock/WhatsMyName:** публичный opt-in OSINT, источники и неоднозначность; username match не подтверждает личность. Не дублируй два инструмента без дополнительной пользы.

Camofox, BrowserOS, Mullvad, OnionClaw, Maxun, clawsec и awesome-privacy по умолчанию остаются reference, а не новыми runtime-компонентами. Их перенос в implementation требует отдельного gap и решения. Установка security-skills не заменяет security engineering приложения.

Выход: измеренная польза и стоимость, принятое решение, тесты, feature flag/rollback, обновлённые инструкции. «Репозиторий скачан» не является успешной интеграцией.
